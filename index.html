Problem Overview

One notification, many possible destinations

In modern systems, one notification may need to be routed to one of several destinations — Email, SMS, a mobile app, an admin dashboard, a security team, or an emergency service. Sending the same notification to every destination is inefficient. A DEMUX gives a conceptual digital routing model where one input reaches exactly one selected output, and the select lines determine the destination.

The real-world scenario

An alert generated anywhere in a system — a sensor, a payment gateway, an auth service — must reach exactly one appropriate channel, not all of them at once.

The proposed solution

  1. Generate notification
  2. Identify destination
  3. Convert destination to select-line combination
  4. Pass notification through DEMUX
  5. Route to selected output
  6. Generate delivery result
  7. Log the delivery
  8. Handle invalid destinations
  9. Display statistics

Assumptions

Scope of this simulation

  • One notification is generated and routed at a time.
  • Only one destination is selected at a time.
  • The DEMUX performs one-to-many routing; only one output is ever active.
  • Select lines determine the active output deterministically.
  • Synthetic data is used for demonstration.
  • No real email, SMS, or WhatsApp message is ever sent.
  • The website simulates delivery only.
  • Delivery status is logged locally in the browser.
  • Invalid destinations are rejected, not routed.
  • Binary select-line combinations map directly to destinations.

DEMUX Theory

What is a Demultiplexer?

A Demultiplexer is a combinational digital circuit that takes one data input and routes it to one of several outputs, based on the values placed on its select lines. Only one output is active at any time — the one whose binary address matches the select-line combination.

Structure

Data Input (D) — the single signal to be routed.
Select Lines (S) — n binary lines that address one of 2ⁿ outputs.
Outputs (Y0…Yn-1) — exactly one carries D; the rest stay 0.

Routing principle

The select lines are decoded into a binary index. That index selects exactly one output line, which is then set equal to D. Every other output remains 0, regardless of D.

General structure (1:4 DEMUX)

             ┌─────────────┐
D  ─────────►│             ├──► Y0
             │    DEMUX    ├──► Y1
S1 ─────────►│             ├──► Y2
S0 ─────────►│             ├──► Y3
             └─────────────┘

Boolean Expressions

DEMUX logic expressions

For a 1:4 DEMUX: Y0 = D·S1'·S0'   Y1 = D·S1'·S0   Y2 = D·S1·S0'   Y3 = D·S1·S0. Each output equals D only when the select lines match its own binary address; otherwise it is 0. Try it live: the expression updates automatically in the simulator as you flip switches.

MUX vs DEMUX

A quick comparison

Multiplexer (MUX)

Many inputs → one output. Select lines choose which input is passed through.

Demultiplexer (DEMUX)

One input → many outputs. Select lines choose which output receives the input. This is the concept used throughout this project.

Types of Demultiplexer

1:2, 1:4, 1:8 and 1:16

Number of outputs = 2ⁿ, where n is the number of select lines.

1:2 DEMUX

1 select line → 2 outputs. Simplest routing decision: on/off between two channels.

Applications: two-way signal steering, simple channel toggling.

1:4 DEMUX

2 select lines → 4 outputs. Used in this project's simulator for a compact 4-destination example.

Applications: small routing banks, memory bank selection.

1:8 DEMUX

3 select lines → 8 outputs. Drives the Notification Router, mapping to 8 real destinations.

Applications: multi-channel notification routing, address decoding.

1:16 DEMUX

4 select lines → 16 outputs. Shown conceptually; the simulator focuses on 1:2/1:4/1:8 for clarity.

Applications: large-scale channel/address decoding.

FAQ

Frequently asked questions

What is a DEMUX? +
A combinational circuit that routes one input to one of several outputs, chosen by select lines.
How many outputs does a 1:8 DEMUX have? +
Eight outputs (Y0–Y7), addressed by 3 select lines.
How are select lines used? +
Their binary combination is decoded into an index; that index's output carries the data input.
How does notification routing work here? +
The chosen destination is converted into a 3-bit select-line value, which drives a real 1:8 DEMUX computation.
What happens with an invalid destination? +
It is rejected before reaching the DEMUX and logged as INVALID DESTINATION — nothing is routed.
Does the website send real SMS or email? +
No. This is entirely a simulation; no real messages are ever sent.
What is synthetic data? +
Deterministically generated sample notifications used to demonstrate routing at scale without real user data.
Why are test cases required? +
They verify the DEMUX logic and routing pipeline behave correctly for both normal and edge/fault inputs.
How does DEMUX relate to digital routing? +
DEMUX is the fundamental digital-logic building block behind one-to-one channel selection, which is exactly what notification routing needs.
